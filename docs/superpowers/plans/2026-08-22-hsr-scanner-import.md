# HSR-Scanner 帐号资料导入计划

## 目标

让帐号页可在浏览器内导入 HSR-Scanner v4 的分段 JSON，并把角色以较高投入合并、把非空光锥与遗器分类作为快照写入用户明确指定的九位 UID。原始扫描档、开拓者标识与详细遗器词条不上传、不提交，也不进入公开档案。

## 已验证输入

- 两份样本均为 `source: HSR-Scanner`、`build: v1.5.0`、格式版本 4。
- 角色扫描包含 63 个角色；装备扫描包含 341 个光锥实例与 2869 个遗器实例。
- 全部 ID 均可映射到 `4.4-cn-2026-08-21`。
- `metadata.uid` 均为空，且 `metadata.trailblazer` 不一致，不能把 metadata 当作帐号身份。
- 341 个光锥实例仅对应 114 种光锥，现行按种类去重会丢失 227 个实例。

## 设计裁决

1. 扫描档导入必须由用户明确输入或选择目标 UID；若扫描档未来携带非空 UID，则必须与目标 UID 完全一致。
2. 角色采用较高投入合并语义。非空光锥／遗器数组会替换该分类先前的扫描器来源实例，同时保留手动与 legacy 实例；空数组代表本次未扫描该分类，保留既有分类。
3. 帐号 schema 升至 v2；光锥以 `instanceId` 区分多个副本。旧 v0/v1 记录和 v1 备份会生成稳定的 legacy 实例 ID 后迁移。
4. 保存最小可用库存：角色 ID、等级、星魂；光锥本地快照实例 ID、种类、等级、叠影；遗器本地快照实例 ID、套装、部位。扫描器 `_uid` 每次扫描可任意变化，不作为持久身份且不保存。扫描器 build、格式版本、导入时间与各分类数量写入本地来源记录。
5. 不保存扫描档文件名、开拓者 metadata、技能／行迹扫描值、遗器主副词条、锁定与装备位置。当前推荐器尚不计算这些字段，保存它们只会扩大隐私面与迁移成本。
6. 公共档案继续使用独立最小 schema，不公开实例 ID 或扫描来源；公开仍须逐次明确同意。
7. 队伍装备分配按光锥实例消费；同种光锥有多个副本时按叠影、等级、实例 ID 的稳定顺序选择，不重复使用实例。

## TDD 顺序

1. 解析与映射测试：v4、UID 绑定、未知／错误格式、分段数组。
2. schema 迁移测试：v1 光锥生成实例 ID，v2 重复种类但实例唯一。
3. 服务测试：两份分段扫描合并、`_uid` 重排／删除／升级后的快照替换、空分类保留、跨版本与未知引用原子失败。
4. 分配测试：同种光锥的两个实例能分别分配给两名角色。
5. UI 测试：选择 JSON、目标 UID 与资料版本后导入，显示摘要且不要求公开同意。
6. 用用户提供的两份本地附件执行非提交验证，再运行 `npm run check` 与 E2E。
